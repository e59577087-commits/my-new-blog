# 合并全屏壁纸模式设计

## 目标

删除现有“全屏壁纸”模式的独立功能，将现有“全屏透明”模式作为唯一的全屏壁纸效果，并在外观设置菜单中把它显示为“全屏壁纸”。

## 当前行为

- `fullscreen` 会把壁纸铺满页面，并在浅色主题下叠加较强的白色遮罩。
- `transparent` 同样把壁纸铺满页面，同时使用更轻的遮罩并让内容表面呈透明玻璃效果。
- 两个模式在菜单中同时出现，功能高度重合。

## 选定方案

以 `transparent` 作为保留模式的内部规范值：

- 从菜单删除 `data-value="fullscreen"` 按钮。
- 将 `data-value="transparent"` 按钮文案从“全屏透明”改为“全屏壁纸”。
- 壁纸模式合法值收敛为 `banner`、`transparent` 和 `solid`。
- 删除所有只服务于 `fullscreen` 的 CSS 规则，并从共享选择器中移除 `fullscreen`；`transparent` 的现有全屏壁纸和透明表面效果保持不变。
- 读取或应用旧设置时，把遗留的 `fullscreen` 值规范化为 `transparent`，使原用户立即进入保留下来的全屏壁纸效果。用户下一次修改外观设置时，规范值会写回现有存储项。

保留 `transparent` 内部值可以避免重命名仍在使用的样式分支；界面文案负责表达用户可见的“全屏壁纸”概念。

## 数据流与容错

页面读取 `blog-appearance-settings-v1` 后，先迁移遗留的 `fullscreen`，再校验允许的模式并写入根元素的 `data-wallpaper-mode`。未知值、损坏的 JSON 和不可用的本地存储仍沿用现有回退行为，不改变默认的 `banner` 模式。

## 范围

- 修改外观设置菜单中的壁纸模式选项。
- 修改基础布局中的壁纸模式规范化逻辑。
- 清理全局样式中的旧 `fullscreen` 实现与选择器。
- 增加针对菜单、迁移逻辑和 CSS 清理的回归测试。

不改变壁纸图片、默认壁纸模式、其他主题设置、页面布局或 `transparent` 模式的视觉参数。

## 验证

- 菜单只显示“横幅壁纸”“全屏壁纸”“纯色背景”，且只有一个“全屏壁纸”选项。
- 选择“全屏壁纸”会应用内部 `transparent` 模式及其现有透明玻璃效果。
- 遗留 `fullscreen` 设置会规范化为 `transparent`，其他未知值仍回退到 `banner`。
- 生产组件和 CSS 中不再存在可选或可应用的 `fullscreen` 模式分支；唯一保留的 `fullscreen` 字面量只用于旧设置迁移。
- 相关回归测试与完整站点构建通过。
