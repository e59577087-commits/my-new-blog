# 修复全屏壁纸黑洞黑圈设计

## 目标

消除全屏壁纸模式下黑洞周围额外出现的大面积黑圈，使黑洞核心、吸积盘、光子环和引力透镜效果与横幅壁纸模式保持一致。

## 根因

全屏壁纸由 `body` 背景绘制，首页的 `.home-black-hole-scope` 本身保持透明。黑洞纹理捕获目前只把该 scope 交给 `html2canvas`，并使用透明画布背景，因此捕获结果没有包含位于祖先元素上的全屏壁纸。

片元着色器的 `pageAt` 只读取捕获纹理的 RGB 通道。透明像素的 RGB 为黑色，当透镜区域变为不透明并放大这些像素时，就形成黑洞外围的大面积黑圈。横幅壁纸直接绘制在 `.home-hero-banner` 上，捕获纹理是完整的，所以没有同样的问题。

## 选定方案

只修复离屏纹理的背景合成，不改变实时页面或着色器：

- 每次捕获前读取真实 `body` 的计算背景属性，包括颜色、图像、位置、尺寸、重复方式、固定方式、原点和裁剪方式。
- 在 `html2canvas` 的 `onclone` 阶段，把这些背景属性应用到克隆的 `.home-black-hole-scope`，使离屏截图包含用户实际看到的页面底层背景。
- 继续移除克隆中的黑洞画布，并继续还原被黑洞暂时扭曲的 DOM 元素，避免递归捕获或重复变形。
- 保持现有的横幅区域裁剪、纹理分辨率、性能上限、着色器、黑洞尺寸、吸积盘参数和动画状态机不变。
- 对所有壁纸模式使用同一背景合成路径；横幅壁纸本身是不透明的，因此视觉结果不变，纯色和全屏壁纸则能获得正确底色。

该方案仅改变截图输入，黑洞输出仍完全由同一套着色器生成，因此最符合“全屏壁纸模式与横幅壁纸模式一致”的要求。

## 数据流与容错

外观模式或主题变化后，现有 `MutationObserver` 继续触发延迟重抓：读取当前 `body` 背景，克隆首页 scope，补入背景，生成纹理并上传 WebGL。若背景读取或截图失败，沿用现有 `textureReady = false` 与警告逻辑，不新增阻塞页面的错误状态。

背景属性只写入 `html2canvas` 创建的克隆文档，不修改真实 DOM，也不会让首页实际多出一层壁纸。

## 范围

- 修改 `HomepageBlackHole.astro` 的纹理捕获准备逻辑。
- 增加针对 body 背景合成、克隆隔离和模式变化重抓的回归测试。
- 手动比较横幅壁纸与全屏壁纸模式下的黑洞边界。

不调整壁纸图片、壁纸模式、黑洞着色器公式、吸积盘预设、运动轨迹、尺寸周期、粒子交互或其他页面样式。

## 验证

- 全屏壁纸模式下不再出现由透明纹理造成的大面积黑圈。
- 横幅壁纸与全屏壁纸模式下，黑洞核心、吸积盘、光子环和透镜边界一致。
- 切换壁纸模式和明暗主题后，纹理会按当前背景重新生成。
- 真实页面 DOM 不会被写入额外背景样式。
- 新增回归测试、现有黑洞相关测试和完整生产构建通过。
