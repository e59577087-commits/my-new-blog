# QuickClipboard 行内图片排版修复设计

## 背景

`QuickClipboard.md` 使用 Obsidian 图片语法为截图声明宽度，并把需要并排的图片写在同一段落中，例如：

```md
![[QuickClipboard-90b5432cc26a1a49.png|250]]![[QuickClipboard-68356382664f09e5.png|254]]
```

Remark 转换结果正确：两张图片相邻，并分别带有 `width="250"` 与 `width="254"`。浏览器运行灯箱增强脚本后，宽度大于 160px 的图片被判定为 `block` 模式，分别包进宽度为整篇文章宽度的按钮，因此相邻图片被强制拆成两行。

## 目标

- 显式声明宽度的文章图片保留作者在 Obsidian 中设置的宽度。
- 相邻图片在桌面端空间足够时自然并排。
- 可用宽度不足时自然换行，不产生横向滚动。
- 中等尺寸截图继续支持点击查看大图。
- 未声明宽度的正文大图继续使用整行灯箱布局。
- 保留现有小尺寸 PNG 表情或装饰图的排除规则。

## 非目标

- 不修改 `QuickClipboard.md` 的图片语法或手动添加 HTML 容器。
- 不引入固定双列网格，不统一覆盖图片的原始声明宽度。
- 不重构整个 Markdown 渲染或灯箱组件。

## 设计

### 灯箱模式判定

在 `getArticleImageLightboxMode` 中继续优先处理显式偏好以及不支持灯箱的格式：`off` 始终关闭灯箱；`on` 在存在声明宽度时使用 `thumbnail`，没有声明宽度时使用 `block`。

自动判定规则调整为：

1. 宽度不超过 160px 的图片继续沿用现有规则：PNG 不启用灯箱，其他受支持格式使用紧凑灯箱。
2. 宽度大于 160px 且显式声明宽度的受支持图片使用 `thumbnail` 模式。该模式的外层按钮读取声明宽度并保持 `inline-block`，允许相邻图片共处一行。
3. 未声明宽度的受支持正文图片继续使用 `block` 模式并占满文章宽度。

现有 `.article-image-trigger--thumbnail` 已通过 `--article-image-thumbnail-width` 保存图片宽度，并使用 `max-inline-size` 限制窄屏溢出，因此无需添加新的布局容器。

### 数据流

1. Obsidian `|宽度` 经 `remark-obsidian.ts` 转为 `<img width="…">`。
2. 灯箱初始化读取 `width` 属性并调用 `getArticleImageLightboxMode`。
3. 显式宽度截图得到 `thumbnail` 模式。
4. 灯箱组件生成与图片同宽的行内按钮；浏览器根据剩余行宽决定并排或换行。

### 兼容与降级

- 图片宽度超过文章区域时由 `min(100%, 声明宽度)` 收缩到容器宽度。
- JavaScript 未运行时，原始 `<img width>` 仍由现有 `.prose-tech img[width]` 规则行内显示。
- GIF、SVG、空替代文本及显式关闭灯箱的图片维持原有行为。

## 测试与验收

### 自动化测试

- 新增断言：宽度 250px 的 PNG 教程截图判定为 `thumbnail`。
- 新增断言：显式开启灯箱且声明宽度的图片仍判定为 `thumbnail`。
- 保留断言：宽度 117px 的 PNG 小图判定为 `off`。
- 保留断言：未声明宽度的受支持图片判定为 `block`。
- 运行图片行内布局、文章灯箱及项目构建测试。

### 浏览器验收

在 `/share/quickclipboard/` 验证：

- 250px 与 254px 两张“常规设置”截图处于同一行。
- 258px 与 255px 两张“个性化”截图处于同一行。
- 257px 与 114px 两张“快捷键”截图处于同一行。
- 中等尺寸截图仍显示并可触发“查看大图”。
- 窄屏下图片自动换行且不出现水平滚动。

## 回滚

回滚灯箱模式判定与对应测试即可恢复原行为；文章内容和导入数据不需要回滚。
