# 关于页雨夜窗景首屏实施计划

对应规范：`docs/superpowers/specs/2026-07-11-about-rain-window-design.md`

## 任务 1：建立关于页构建回归测试

**文件**

- 新建：`scripts/about-rain-window.test.mjs`
- 修改：`package.json`

**步骤**

1. 使用 Node 测试运行器执行一次 Astro 生产构建并读取 `dist/about/index.html`。
2. 添加失败断言，要求构建结果包含：
   - 页面根节点 `data-about-rain-window`；
   - 左侧无边框雨景区和右侧内容区；
   - `雨夜小猫.mp4` 视频路径；
   - `autoplay`、`muted`、`loop` 和 `playsinline`；
   - `ABOUT · LIGHT RAIN`、主标题、自述和站点信号；
   - 统计卡位于右侧内容区，而不是雨景之后的独立区块。
3. 读取新窗景组件源码，断言存在 reduced-motion 媒体查询、视频错误降级标记、视差初始化和 `astro:after-swap` 重挂载入口。
4. 读取页面及组件样式，断言包含桌面双栏、移动端单列和视频 `object-fit: cover` 规则。
5. 在 `package.json` 增加 `test:about` 命令。
6. 运行 `npm run test:about`，确认测试因新结构尚未实现而失败。

## 任务 2：准备视频静态兜底画面

**文件**

- 新建：`public/雨夜小猫-poster.webp`

**步骤**

1. 从 `public/雨夜小猫.mp4` 选择一帧能够清楚看到小猫、且左右明暗适合窗景裁切的画面。
2. 使用浏览器视频帧加 Canvas 导出的方式生成 WebP；该过程只生成最终图片，不把临时提取页面或脚本留在仓库。
3. 将图片尺寸控制在足以覆盖桌面窗景、文件大小显著低于视频的范围内。
4. 目视检查 poster 与视频首帧切换时没有明显构图跳变。

## 任务 3：让统计卡支持窄栏布局

**文件**

- 修改：`src/components/StatsCard.astro`

**步骤**

1. 新增可选 `variant` 属性，默认值保持现有页面的外观，关于页传入 `compact`。
2. `compact` 变体移除组件自带的大上边距，减小内边距、图标和数字尺寸，使三项数据能稳定放入左栏。
3. 保留文章数、访问量与运行天数的现有数据逻辑，不增加数字递增动画。
4. 不改变默认变体的 class 和行为，避免影响其他潜在调用方。
5. 运行已有构建，确认 Supabase 未配置或请求失败时仍显示 `-`，不阻塞页面。

## 任务 4：实现独立雨夜窗景组件

**文件**

- 新建：`src/components/AboutRainWindow.astro`

**步骤**

1. 输出语义清晰的雨景容器、视频区和纯氛围层。
2. 视频设置 `src="/雨夜小猫.mp4"`、`poster="/雨夜小猫-poster.webp"`、`autoplay muted loop playsinline`，不显示控件，也不提供声音。
3. 使用 scoped CSS 构建无边框视频面、玻璃反光、暗角和低对比雨痕；不添加外框、横竖格栅、窗台或植物，装饰元素全部 `aria-hidden="true"`。
4. 初始状态让窗景轻微模糊且亮度较低；组件挂载后触发约 1.2 秒的清晰过渡，并派发窗景就绪事件供左栏开始入场。
5. 桌面端监听容器内 `pointermove`，通过 CSS 变量驱动视频与前景进行小幅差速位移；`pointerleave` 时平滑回正。
6. 视频触发 `error` 时给容器添加降级状态，保留深蓝渐变和 poster，不影响页面内容。
7. 在 `prefers-reduced-motion: reduce` 下停止雨痕和视差、不自动播放视频，并直接展示 poster 与最终清晰状态。
8. 初始化函数保证同一组件实例只初始化一次，并在 `astro:after-swap` 后为新页面实例重新挂载。

## 任务 5：重构关于页为单首屏构图

**文件**

- 修改：`src/pages/about.astro`

**步骤**

1. 保留 `getPublishedArticles()` 及文章数量计算。
2. 移除空白内容区和独立的 `SectionTitle`，导入 `AboutRainWindow`。
3. 输出带 `data-about-rain-window` 的单首屏容器，视觉上为左侧雨景区与右侧内容区。
4. 右侧依次输出：页面标识、主标题、自述、在线信号和 `StatsCard variant="compact"`；DOM 仍保持内容优先，通过 CSS 网格区域调整视觉顺序。
5. 初始隐藏左侧各内容项；收到窗景就绪事件后，按页面标识、标题、自述、状态、统计卡的顺序淡入并轻微上移。完整序列在 2.2–2.6 秒内结束。
6. 动画状态仅在本次页面实例内改变一次，不因滚动、指针或视频循环重新触发。
7. 桌面端使用约 60%/40% 双栏，雨景在左、内容在右，并在页头和页脚之间尽量保持单视口构图。
8. 桌面雨景通过组件外扩变量只向左、向上和向下延展，右边界与文字栏间距不变；外扩量限制在设计范围内并保留页面安全留白。
9. 移动端改为雨景在上、内容在下的单列，只增加雨景高度，不使用负向水平外扩，让页面自然增长且不产生横向滚动。
10. 页面外围复用全站 `--page-background` 和文字语义变量，统计卡恢复现有深浅色玻璃样式；视频保持雨夜暗色，并在靠近文字的一侧使用渐变融合，同时保证正文、焦点状态和统计信息的对比度。
11. reduced-motion 模式下直接显示内容最终状态，不执行位移或延迟。

## 任务 6：验证行为、性能与回归

**自动验证**

```powershell
npm run test:about
npm run test:sections
npm run test:obsidian
npm run test:toc
npm run test:external-links
npm run test:study
npm run build
```

**浏览器目视验证**

1. 桌面宽屏和常见笔记本尺寸：雨景在左侧，统计卡和文字在右侧，页脚不会覆盖内容。
2. 手机窄屏：雨景与内容上下排列，无横向滚动，小猫没有被关键裁切。
3. 首次入场：先看到窗景由模糊变清晰，再看到左侧五组内容依次显现。
4. 视频循环：不会再次触发左侧入场动画。
5. 指针交互：视差幅度克制，移出后平滑复位，不引发布局抖动。
6. 视频失败：临时改错视频路径后仍显示可读的渐变窗景和完整左栏；验证后恢复路径。
7. reduced-motion：系统偏好开启时使用静态 poster，无雨痕、视差和入场延迟。
8. 明暗主题：页面外围与其他页面背景一致，视频仍保留雨夜氛围，文字与统计分隔线清晰。
9. 检查视频与 poster 的网络加载大小，确认没有重复请求或意外预加载其他大资源。

最后运行 `git diff --check` 和 `git status --short`，确认没有提交临时帧提取文件、构建产物、开发日志、可视化草图或其他无关文件。
